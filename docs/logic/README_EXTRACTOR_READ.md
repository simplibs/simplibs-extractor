# 📖 `logic/read` — Phase 2: What Is in the Files

The second phase takes the files the [select phase](README_EXTRACTOR_SELECT.md) chose and gives **each one a
verdict**: its text goes on, or it stays out with a reason. It is where the disk is first asked about
content — whether a file is text at all, whether it is an earlier output, whether it is too large — and where
the text is finally read.

```
path ──► binary? ──► generated by us? ──► too large? ──► read ──►  (FileReport "ok", text)
           │               │                   │            │
           ▼               ▼                   ▼            ▼
        skipped         skipped             skipped       error      (FileReport, None)
```

The phase **never raises for a file's own problems**. A file that cannot be used is a `FileReport` with a
reason — one bad file must not stop a run over a thousand. It also **never decides which files take
part**; that was the select phase.

```python
from simplibs.path import normalize_path
from simplibs.extractor.logic import read_source

root = normalize_path("my_project")
report, text = read_source(root / "src" / "app.py", root, 1_000_000)

report.status, report.relative                          # -> ('ok', 'src/app.py')
type(text)                                              # -> <class 'str'>

report, text = read_source(root / "logo.png", root, 1_000_000)
report.status, report.reason, text                      # -> ('skipped', 'not a text file', None)
```

In `extract()`, the loop calls `read_source` for every selected file, and — for the files that came back with
text — runs the [transform phase](README_EXTRACTOR_TRANSFORM.md) on it.

## Skipped or error

| Status      | Meaning                                                              | Makes the run unsuccessful? |
|-------------|----------------------------------------------------------------------|:---------------------------:|
| `"skipped"` | The file was left out **on purpose**; nothing is wrong.              | no                          |
| `"error"`   | The file was meant to be included and **could not be** read.         | yes                         |

## The order of the checks

Cheapest first — and each check is placed so that it gives the **truest reason**:

| #   | Check                      | Cost                                  | Outcome if it fires                                       |
|----:|----------------------------|---------------------------------------|-----------------------------------------------------------|
| 1   | binary content             | the first 8 KB                        | `skipped` — `not a text file`                             |
| 2   | generated by this library  | the first 3 lines                     | `skipped` — `generated by simplibs-extractor`             |
| 3   | larger than the limit      | one `stat`                            | `skipped` — `too large (N > LIMIT bytes)`                 |
| 4   | the read itself            | the whole file                        | `error` — `read failed: …` if it cannot be read as text   |

An earlier output is usually larger than the limit. If the size check came first, it would be reported as
*"too large"* and hide the real reason — which is why the marker is checked before the size.

## What the text is

`read_text` of `simplibs-file` reads the file as **UTF-8** (a byte-order mark is removed if there is one) with
strict decoding, and returns it with the line endings normalized to `"\n"`. A file that passes the text check
on its first bytes but is not valid UTF-8 further on fails the read and becomes an `error`.

## What is public

Both functions are declared in the `__all__` of `simplibs.extractor.logic`, and are **not** exported from the package
root. Your programs call `extract()`; these two are documented for readers who want to know what a verdict
rests on, for tools built on the extractor and for tests.

### `read_source`

**Reads one file into an extraction, or says why it stays out.**

**Parameters:**

| Name       | Type          | Description                                                                    |
|------------|---------------|--------------------------------------------------------------------------------|
| `path`     | `Path`        | The absolute path of the file.                                                 |
| `root`     | `Path`        | The source folder — the base of the relative path in the report.               |
| `max_size` | `int \| None` | The largest allowed size in bytes; `None` switches the limit off.              |

**Returns:** a pair `(FileReport, str | None)` — the report of the file and its text. The text is `None`
unless the status is `"ok"`.

**Raises:** nothing for the file's own problems. A file that cannot be read is reported as `error`. Only
library cards and operating-system errors are turned into a report; a bug in the code itself is **not**
dressed up as a file problem.

**Example usage:**

```python
from simplibs.path import normalize_path
from simplibs.extractor.logic import read_source

root = normalize_path("my_project")
limit = 1_000_000

# 1. A text file
report, text = read_source(root / "src" / "app.py", root, limit)
report.status, report.reason, report.bytes_in           # -> ('ok', None, 62)
report.bytes_out                                        # -> 0        the transform phase fills it in

# 2. Binary content stays out
report, text = read_source(root / "logo.png", root, limit)
report.status, report.reason, text                      # -> ('skipped', 'not a text file', None)

# 3. An earlier output stays out — even when it is larger than the limit
report, text = read_source(root / "extraction.md", root, limit)
report.status, report.reason                            # -> ('skipped', 'generated by simplibs-extractor')

# 4. Too large
report, text = read_source(root / "data" / "dump.json", root, limit)
report.status, report.reason                            # -> ('skipped', 'too large (1500000 > 1000000 bytes)')

report, text = read_source(root / "data" / "dump.json", root, None)       # no limit
report.status                                           # -> 'ok'

# 5. A file that cannot be read as text fails alone
report, text = read_source(root / "notes_cp1250.txt", root, limit)        # not valid UTF-8 after the first 8 KB
report.status                                           # -> 'error'
report.reason                                           # -> 'read failed: ConversionError: ...'
```

**The reasons**, as they appear in `FileReport.reason`:

| Status      | Reason                                         | `bytes_in`        |
|-------------|------------------------------------------------|-------------------|
| `"skipped"` | `not a text file`                              | `0`               |
| `"skipped"` | `generated by simplibs-extractor`              | the file's size   |
| `"skipped"` | `too large (SIZE > LIMIT bytes)`               | the file's size   |
| `"error"`   | `read failed: <ErrorName>: <first line of the message>` | `0`     |

An error reason is **one line**: the name of the exception and the first line of its message that holds a
letter or a digit, so the frame lines of a diagnostic card are skipped. A report lists many files; the full
card is for the person debugging one failure.

**Why a pair.** The report is always there — for every file, whatever happened — and the text only when there
is one. The caller adds the report to the result in all cases and goes on with the text only for `ok`.

**Why `skipped` and `error` are different.** A skipped file does not make the run unsuccessful; an error
file does. The caller is told apart *"nothing is wrong"* from *"something needs a look"*.

**Why the catch is narrow.** Only `SimpleException` (library cards) and `OSError` are caught. A file that
vanished, is locked or is not valid text fails alone; an `AttributeError` in this very function would still
show up as the bug it is.

<details>
<summary>🔍 Under the hood</summary>

```python
def read_source(
    path: Path,
    root: Path,
    max_size: int | None,
) -> tuple[FileReport, str | None]:

    # 1. The path as the report and the output will show it
    relative = relativize_path(path, root=root).as_posix()

    try:
        # 2. Binary content never enters a text output
        if not is_text_file(path):
            return FileReport(path, relative, "skipped", "not a text file"), None

        # 3. Generated output, before the size limit: outputs are usually large
        size = file_size(path)
        if is_generated_file(path):
            return FileReport(path, relative, "skipped", "generated by simplibs-extractor", size), None

        # 4. Too large to be useful
        if max_size is not None and size > max_size:
            return FileReport(path, relative, "skipped", f"too large ({size} > {max_size} bytes)", size), None

        # 5. Read it
        text = read_text(path)

    # 6. A file that vanished, is locked or is not valid text fails alone; the run continues
    except (SimpleException, OSError) as exc:
        return FileReport(path, relative, "error", f"read failed: {describe_failure(exc)}"), None

    # 7. Included
    return FileReport(path, relative, "ok", None, size), text
```

The one-line description of a failure is shared by the phases that report per-file failures (read, transform):

```python
def describe_failure(exc: BaseException) -> str:

    # 1. Split the printed message into stripped lines
    lines = [line.strip() for line in str(exc).splitlines()]

    # 2. The first line with real content; frames and blank lines have none
    message = next((line for line in lines if any(char.isalnum() for char in line)), "")

    # 3. The class name is always shown; the message only if there is one
    name = type(exc).__name__
    return f"{name}: {message}" if message else name
```

It reads the **printed** text, not the fields of a card, so it works for every exception, with a card or
without.

### `is_generated_file`

**Checks whether a file is an output of this library** — by the marker in its first lines, whatever the
file is called.

**Parameters:**

| Name   | Type   | Description             |
|--------|--------|-------------------------|
| `path` | `Path` | The file to check.      |

**Returns:** `bool` — `True` if `GENERATED_MARKER` appears in the first `MARKER_SCAN_LINES` (three) lines.

**Raises:** the cards of `iter_lines` if the path is not a regular file (`NotFoundError`, `StateError`).
Undecodable bytes never raise — they become replacement characters.

**Example usage:**

```python
from pathlib import Path
from simplibs.extractor.logic import is_generated_file

is_generated_file(Path("my_project/extraction.md"))             # -> True     an output of this library
is_generated_file(Path("my_project/extraction (1).md"))         # -> True     under another name — still recognized
is_generated_file(Path("my_project/README.md"))                 # -> False    an ordinary file
is_generated_file(Path("my_project/empty.txt"))                 # -> False    nothing to find
```

**Why the marker and not the name.** The `unique` policy writes `extraction (1).md` and `backup` keeps the old
output under another name — names nobody can list in advance. The marker is in the **content**, so it holds
for all of them.

**Why only the head.** An output is large. `iter_lines` reads in blocks and the stream is closed right after
the first lines, so a multi-megabyte output costs a few kilobytes.

**Why `errors="replace"`.** This is a question about a marker, not a read of the content. A file with an odd
byte near its start can still be checked; whether it can be **read** is decided later, by `read_text`.

**The marker is a plain substring.** It sits inside a comment whose syntax depends on the format
(`<!-- … -->` in Markdown, `# …` in plain text), so the check looks for the text, not for a syntax. An output
of a format you registered yourself must write the marker in its first lines (see
[`GENERATED_MARKER`](../README_EXTRACTOR_CONSTANTS.md#generated_marker)), otherwise it is read as an ordinary
file next time.

<details>
<summary>🔍 Under the hood</summary>

```python
def is_generated_file(path: Path) -> bool:

    # 1. Stream the head only; undecodable bytes become replacement characters, never an error
    lines = iter_lines(path, errors="replace")
    with closing(lines):
        head = list(islice(lines, MARKER_SCAN_LINES))

    # 2. The marker is a plain substring: it sits inside a comment whose syntax depends on the format
    return any(GENERATED_MARKER in line for line in head)
```

`closing` releases the file as soon as the head is taken; the iterator is never exhausted.

</details>
